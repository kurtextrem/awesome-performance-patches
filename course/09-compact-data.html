Pack data tightly

When you keep thousands of records, their fields can take up space and scatter the values you read together. You can pack yes or no fields together and keep frequently read numbers side by side.

What you will learn
  • Store several true or false values in one number and read them back.
  • Keep numeric fields in separate arrays and use a matching position to read a record.

How can one number store several answers?

The ideaGive each yes or no field its own digit in a number written in base two.

Walk through it

A note can be archived, starred, pinned, or unread. An object can store four separate booleans, which are values that are either true or false.

A bit is one digit in base two, so it can be zero or one. A bit flag uses that digit to store one true or false answer.

Read the first diagram from right to left for the bit values. Unread is worth one and starred is worth four. Both are on, so this note's four flags fit in the number five.

With a hundred thousand notes, four separate boolean fields mean four hundred thousand stored field values. Packing them means each note stores one number.

The fix

Name each flag and use |, called bitwise OR, to combine them. It keeps a bit on if either input has that bit on.

The number that selects a bit is called a mask. To test STARRED, use &, called bitwise AND, which keeps a bit only if both inputs have it on. The second diagram shows why the result stays nonzero.

// Before
const note = { archived: false, starred: true, pinned: false, unread: true };
const wasStarred = note.starred;

// After
const UNREAD = 1, PINNED = 2, STARRED = 4, ARCHIVED = 8;
const flags = STARRED | UNREAD;
const isStarred = (flags & STARRED) !== 0;

Watch out

  • Keep the flag names beside the code that packs and reads them. Keep plain booleans where they make the rest of the code easier to read.
  • Bitwise operators on JavaScript Number values use 32 bits. Wider sets need another representation, such as BigInt for larger whole numbers or several words in a typed array. Rollup used BigInt flags for sets of dependencies, and Parcel moved its large flag sets to typed arrays.

Evidence

Node made the state object for readable streams about 40 percent smaller by storing its booleans as bits in one number.

Why keep each numeric field in its own array?

The ideaGroup values by field so a loop reading one field can step through neighbouring numbers.

Walk through it

Three product rows each hold a price and a stock count. If you add the prices, a loop finds each row object and reads its price.

A typed array stores values of one numeric type side by side. Make one for prices and one for stock counts. The first slot of each array belongs to the first product.

In the diagram, green marks prices two, five and eight. With columns, the loop reads those prices in order from a single block of numbers.

At a hundred thousand products, the loop still reads a hundred thousand prices. The price column keeps consecutive reads close together, which can help when the processor fetches memory in blocks.

The fix

Use one typed array per field, a layout called struct of arrays. A Float64Array can hold prices with fractions. A Uint32Array holds nonnegative whole numbers in a fixed range, which works for these stock counts.

Size both arrays from the input list and fill them using the same row positions. Then a loop that adds prices can read price alone.

// Before
const oldTotal = rows.reduce((sum, row) => sum + row.price, 0);

// After
const price = Float64Array.from(rows, (row) => row.price);
const stock = Uint32Array.from(rows, (row) => row.stock);
const newTotal = price.reduce((sum, value) => sum + value, 0);

Watch out

  • Choose a type that fits the data. For example, Uint32Array converts fractions and wraps numbers outside its range.
  • Keep row positions aligned across columns when you reorder them. Conversion takes work up front, so measure it too if you only scan once.

Evidence

A FOSDEM talk reported about 9 nanoseconds per sample for a profiler query after its numeric data moved into separate typed columns.

Remember

  • A bit flag gives one true or false field a named position in a number.
  • A mask selects that position so you can check it with AND.
  • Typed columns keep the values for one field side by side.

Quick check

What does the pinned mask return when the stored flags equal five?

AND returns zero because five turns on the starred and unread bits. The pinned mask only keeps the bit worth two, which is off.

Which values describe the second product in the column diagram?

Read the second slot from each column to get a price of five and a stock count of three. Both slots refer to the same row.

Would numeric columns always help if every read needs price and stock?

The loop would have to read both columns, so the benefit of reading only prices disappears. Measure the loop and the conversion cost together.
