Skip it or put it off

A page can spend time on work that nobody needs yet, or ever. You can check for work you can skip and move other work to the first time it matters.

What can you rule out before measuring?

The idea

A quick check can skip an expensive step once you know its result cannot affect the answer.

Walk through it

A chart has six labels, each with a center position along the bottom axis. The chart draws a label only if its center is inside the view and its text fits. To find out whether the text fits, the code asks the browser for its width.

Suppose the visible range is 20 through 40. The six centers are 0, 10, 20, 30, 40 and 50. In the first diagram, the top row measures all six labels and then checks their positions. The bottom row checks each center first, which leaves only three measurements.

When a page has pending size or position changes, a width read can make the browser calculate those sizes and positions immediately. That is called forced layout. The second diagram shows where that work can enter the measurement, and Lesson 17 explains when it happens.

With 10,000 candidate labels and 500 centers in view, the same rule leaves 500 width reads on one pass. Real charts may revisit a label, so a count of measurements and a count of points describe different things.

The fix

Return as soon as the center fails the range check. This is an early exit, and the check that causes it is called a guard clause. Candidates that pass still need the original width and fit checks.

const inView = center => center >= 20 && center <= 40;
// Before
const visible = label => {
  const width = measureText(label.text);
  return inView(label.center) && fits(label, width);
};
// After
const visible = label => {
  if (!inView(label.center)) return false;
  return fits(label, measureText(label.text));
};

Watch out

  • Keep the inclusive bounds if labels centered on either edge can appear.
  • If the product allows a label centered outside the view to overlap it, a center check can hide valid labels.

Evidence

Recharts reported about 55 percent fewer text measurements after adding the position check and delaying size reads until needed.

What can wait until someone asks for it?

The idea

A lazy value is calculated on first use, so an unused value never costs a build.

Walk through it

A file page opens on Details and offers a History tab. The History tab groups changes by date for display. With three changes, a build reads all three and groups them, even if the reader stays on Details.

With 10,000 changes, the page can still show Details before it visits any of them. In the diagram, the vertical line marks when Details is ready. Building on first use moves the grouping past that line and into the first History open.

The fix

Build the grouped list inside the open handler and save it for the next open. The ??= operator runs its right side only when the saved value is null or undefined. A second open can render the saved list straight away.

// Before
const groups = groupByDay(changes);
historyButton.onclick = () => renderHistory(groups);

// After
let groups;
historyButton.onclick = () => {
  groups ??= groupByDay(changes);
  renderHistory(groups);
};

Watch out

  • The first open now pays for the build, so measure that interaction as well as page load.
  • When the changes are refreshed, clear the saved groups so the next open builds from the updated list.

Evidence

Chrome DevTools moved about 3.4 seconds of tree building off the load of a large recording by waiting until the views were opened.

Remember

  • Put the guard before the call it can skip.
  • Use the cheap check only when it preserves the answer.
  • Build a lazy value when someone reads it, and clear it when its inputs change.

Quick check

With the guard in place, how many widths do you read if all six centers pass?

You still read six. The guard saves work only for labels it can rule out before the width read.

What happens if History opens twice and the changes stay the same?

The first open groups the changes and stores the result. The second open already has a value, so ??= skips the build.
