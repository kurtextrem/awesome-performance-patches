Faster scripts and tests

A short command can spend most of its time loading files, and a small test can do extra work on the way to one check. You will learn to trim that work while keeping the command and the test doing their jobs.

What you will learn
  • Move an import to the command that uses it.
  • Make a test search less of the page while keeping the same check.
  • Skip browser requests that the test can do without.

Why does a tiny command take so long to start?

The idea Load each module when the command reaches the code that needs it.

Walk through it

A notes tool exports plain text or a PDF. Each writer lives in a module, a file that provides code another file can use. When Node first loads a module, it finds the file, reads and runs it, and loads the other files it asks for.

Suppose the PDF writer loads two helper files and the text writer loads none. If the entry file loads both writers before it checks the format, a text export loads four files beyond the entry file. The load diagram marks the three that a text export can skip.

If the PDF writer and its helpers pull in 30 more files, choosing the text writer first skips all 33. The text writer does the same work once it starts.

The fix

Read the format first and load the matching writer inside that branch. This is lazy loading, which means waiting until the code needs a file before loading it.

// Before: both writers load on every run.
const pdf = require('./pdf');
const text = require('./text');
const writer = format === 'pdf' ? pdf : text;
writer.write(notes);

// After: load only the chosen writer.
if (format === 'pdf') require('./pdf').write(notes);
else require('./text').write(notes);

The same idea works in a VS Code extension, an add-on that runs inside the editor. An activation trigger such as onLanguage:typescript tells the editor to start the extension when a TypeScript file opens.

Watch out

  • Check whether an import sets up anything both commands need. Keep shared setup where both commands run it.
  • Time each format with a fresh process, because the first use of the PDF writer still has to load its files.

Evidence

Delaying and narrowing module loads saved about 40 milliseconds per run in one benchmark of npm run echo.

How much of the page does this test need?

The idea Keep the checks that prove the behavior and cut setup or searching that adds nothing to them.

Walk through it

A page has a note form and a settings form. Each has two text fields. A test checks for the textbox named Title inside the note form.

getByRole looks for an element by its job, such as textbox. It can also match the accessible name, which is the name a screen reader would announce. The first diagram shows the candidates in the page's tree of elements, called the DOM.

If each form grows to 50 fields, the scoped query has 50 textbox candidates instead of 100. It still checks the role and the name of the field it returns.

A browser test that checks whether Save adds a note also loads a preview image. Playwright usually waits for the page's load event, which fires after the page and its resources finish loading. If the image cannot affect Save, stopping its request can remove that wait, as the second diagram shows.

The fix

Component tests usually run in Node with jsdom, a tool that imitates the browser's page structure (the DOM). Two small changes make these tests faster.

Use within(noteForm) to bind the query to the note form. In the browser test, use Playwright's page.route() to stop the preview request before the page loads.

// Testing Library, before
screen.getByRole('textbox', { name: 'Title' });
// Testing Library, after
within(noteForm).getByRole('textbox', { name: 'Title' });

// Playwright, before navigation
await page.route('**/previews/**', route => route.abort());
// Both versions still navigate and check that Save works.
await page.goto('/notes');

Watch out

  • Search the whole page if the test should catch duplicate controls anywhere on the page.
  • Keep the image request if Save depends on it or the test checks how the image appears.

Evidence

Changes to how jsdom finds elements and handles events cut the run time of one large form test by about 40 percent.

Remember

  • Choose the command before you load the code unique to it.
  • Search the smallest area where the test should find the control.
  • Block a browser request only when you can still prove the same behavior.

Quick check

What work does a text export skip when the PDF import moves?

The text export never reaches the branch that loads the PDF writer. That skips the writer itself and every file it alone would have loaded.

When should the title field test still search the whole page?

Keep the whole-page query if the test should fail when two textboxes named Title appear anywhere. A form query only checks the candidates inside that form.

Can a test of the preview image block its request?

The test needs the request because it checks whether the image appears. Blocking that request makes the page take a different path from the one the test should cover.
